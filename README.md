# 工艺工程师工作台

通过网址打开，每个人的数据独立保存在自己的浏览器中。需要分享时，导出文件发给对方，由对方导入使用。登录身份通过 Supabase 账号服务验证。

界面、示例和导入模板使用生产指标、质量指标、资源消耗、损失分析和统计监测等通用分类。资源指标可按各装置的实际名称和单位填写；已有装置名称、用户自定义指标、导入数据和历史快照保留原样，旧版表头仍可识别。

## 发布网址

将本目录中的 `index.html`、`workbench.html`、`assets/`、`.nojekyll` 和 `启动工程师工作台.html` 一起提交到 GitHub 的 `main` 分支。在支持 GitHub Pages 的仓库中：

1. 打开仓库 **Settings → Pages**。
2. 在 **Build and deployment → Source** 选择 **Deploy from a branch**。
3. 选择 **main** 分支和 **/ (root)** 目录，点击 **Save**。
4. 等待部署完成，使用 Pages 页面显示的实际网址。

本仓库的默认网址通常为 `https://seantim-could.github.io/Process-engineer/`；只有 GitHub Pages 部署成功后才能访问。将网址发给对方即可，无需把 HTML 文件逐人发送。`index.html` 是轻量登录页，在整套图表代码加载前就能显示。登录后进入 `workbench.html`，它使用带内容指纹的独立脚本与样式文件，便于缓存；登录页会在空闲时预取这些资源。旧版中文网页地址也会在网站上转到新入口。

## 分享数据

### 分享整个工作空间

1. 发送方在网页顶部点击 **完整备份**，下载 JSON 文件，再通过聊天、邮件等方式发给对方。
2. 接收方打开工作台网址，点击顶部 **恢复备份**，选择收到的 JSON 文件。
3. 核对恢复提示并确认。工作台会先下载接收方当前数据的备份，再替换工作空间。

完整备份包含历史数据、指标配置、计算公式、关注记录、月报，以及个人资料、主题色和文件索引。分享前请确认这些内容都适合提供给对方。文件索引只保存地址，不包含被索引的本机文件本身。

**恢复备份会替换当前工作空间，不会合并。** 接收方应保留自动下载的恢复前备份。浏览器若拦截下载，请先手动点击“完整备份”并确认文件已保存，再执行恢复。

### 只分享部分数据

在 **数据中心** 选择数据，点击 **导出所选数据**，把 CSV 文件发给对方。接收方点击 **导入数据**，选择文件及目标装置，按界面提示核对并保存。

此方式用于导入表格数据，不等同于完整备份：不会一起带走全部个人资料、工作空间设置、计算公式或月报快照。导入遇到同名指标、相同时间及分组的值冲突时，按界面提示核对新旧值。

## 数据保存

- 数据保存在当前浏览器的本地数据库中，不会因为打开网址就自动分享给其他人，也不会自动上传到 GitHub。
- 每个人独立编辑；文件分享后各自保留一份，不会自动同步后续修改。
- 请使用 Chrome 或 Edge 的普通窗口，定期导出完整备份。无痕窗口、清理浏览器数据、更换电脑或网址后，本地数据可能不可用，需要用备份迁移。
- 如果顶部出现“临时模式”，请在关闭窗口前完成备份。
- 从本机 HTML 文件切换到网站时，请先在旧页面导出完整备份，再在网站恢复。
- 本机或共享盘文件路径不会随网站发布变为公开文件；对方需要另行获得文件及访问权限。

## 管理员统一发放账号

本工作台已连接 Supabase 账号服务，通过管理员发放的工号和密码登录。管理员可绑定姓名、工号并生成初始密码，使用者首次登录必须改密。登录后按账号划分本机工作空间；不会自动同步生产数据或上传本机文档。旧版未登录的数据仍保留在原本机数据库中，可在 **账号管理 → 导出旧版本机备份** 导出，再通过顶部 **恢复备份** 迁入当前账号。具体配置和首次管理员创建步骤见 [账号服务启用说明](账号服务启用说明.md)。

## 跨装置计算指标

在 **数据中心 → 新增计算指标** 中，先填写名称、输出单位和公式，再在“点击指标插入引用”区域选择 **引用装置 → 数据分组（生产 / LIMS）→ 分组 / 采样点**，点击指标按钮插入引用。其他装置需要先在当前工作空间导入数据；无需切换当前装置即可引用。

- 计算结果保存在当前装置；跨装置引用同时保存来源数据集、装置、指标和采样点，不会因为不同装置有相同指标名或编号而混用。
- 选择生产时间基准时，使用当前装置、当前分组的生产时间；选择 LIMS 基准时，使用所选主检验位点的采样时间。跨装置按最近时间匹配，距离相同取较早记录。
- 最大匹配时间差可调整；超出限制、最近记录为空、来源被删除或归档时，结果留空并说明原因。LIMS 引用仍遵守共同覆盖时间范围。
- 预览会列出实际匹配的装置、采样时间和时间差。确认后再保存；预览后来源数据有变化时，需要重新预览。
- 引用装置后续导入或修改数据后，会自动重新计算相关指标和后续公式；历史月报快照保持生成时的数据。跨装置循环引用会被拦截。
- 公式按保存时的各引用单位计算，输出单位由你指定，不自动推导量纲。不同单位相加时请明确换算，例如 `kg/h + t/h * 1000`。后续把来源单位改成兼容单位时，会按原引用单位换算，保持已有公式含义。

完整备份包含这些跨装置绑定。要让另一台电脑继续计算，请分享完整备份；单独导出一个装置的 CSV 不会带走其他装置和公式配置。

## 网站与本机文档检索

网站的“文档检索”页提供 **下载 Windows 便携启动器** 和 **打开本机文档检索** 两个按钮。普通使用者可直接从网站下载安装包，完整解压后双击 **ProcessEngineerWorkbench.exe**，无需安装 Python或登录 GitHub。保留启动窗口，再点击 **打开本机文档检索**。每个人仍需 Windows、桌面版 Microsoft Office 及自己的文档权限。详见 [本地检索网站接入说明](本地检索网站接入说明.md)。

**Code → Download ZIP 是源码包，不是免安装 Python 的便携版。** 公开下载链接是 [最新版 Windows 便携启动器](https://github.com/SeanTim-could/Process-engineer/releases/latest/download/Workbench-Windows-Portable.zip)，可直接分享此链接。解压后请保留 `_internal` 目录。

发布到 `main` 的相关更新会在通过 Windows 构建与运行验证后自动发布 GitHub Release，网站的固定下载链接会指向最新成功发布的版本。构建失败时保留上一版下载。Release 文件不受 Actions 构建产物 30 天保留期限的限制。

本机启动器和它使用的本地 HTML 需要单独更新，不会随网站更新而自动替换。这个本机服务固定使用 8765 端口；做静态网页预览时请选用其他端口。

## 本地开发与验证

网页部分已经打包为单个 HTML 文件，不需要安装前端依赖或构建。本机文档检索需要上述 Windows 环境。在仓库根目录执行以下命令，可预览静态网页：

```sh
python3 -m http.server 8766 --bind 127.0.0.1
```

用浏览器访问该服务，验证首页跳转及工作台功能。验证数据分享时，使用两个独立浏览器配置，分别模拟发送方和接收方，检查 CSV 导入、JSON 备份恢复及刷新后的数据保留。

检索逻辑与本机 HTTP 测试：

```sh
cd local_service
python3 -m unittest -v test_documents test_web_entry
```

这些测试使用模拟文档读取器，不代表 Windows Office 或公司文档权限已完成实测。

跨装置计算模块保存在 `frontend/cross-unit-calculations.js`。修改后执行以下命令，将模块同步到单文件网页：

```sh
python3 scripts/sync-cross-unit-calculations.py
python3 scripts/build-web.py
```

浏览器回归测试需要 Node.js、Playwright 和 Chromium，使用隔离的浏览器上下文及虚拟装置数据，不会读取已有工作空间：

```sh
node scripts/test-cross-unit-calculations.cjs
```

可用 `CHROMIUM_PATH` 指定浏览器路径。测试覆盖跨装置生产/LIMS引用、时间匹配、单位变化、后续导入重算、计算依赖、循环引用、备份迁移与实际编辑器操作。GitHub Actions 会自动运行该检查。

修改账号模块后运行 `python3 scripts/sync-account-auth.py`，再运行 `python3 scripts/build-web.py`，同步生成网站入口和缓存资源。网站生成不会拆分便携包使用的单文件 HTML。`node scripts/test-web-entry.cjs` 会阻止重型脚本响应，验证登录页仍能先显示，并检查旧网址、登录后加载和网络超时反馈。
