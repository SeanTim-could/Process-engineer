一、这次交付是什么
新增左侧“文档检索”：选择文件夹、建立/增量更新索引、关键词查找、原文片段、PPT 页码或 Word 正文段落、用本机 Office 打开原文件。
读取沿用已验证的 Python + Microsoft Office 自动化方式；不会上传文档，不绕过公司授权、不保存或修改原文件。
本包是可运行源代码整合版，尚不包含已构建的 Windows exe。生成同事无需安装 Python 的分发包，需在 Windows 上执行附带的打包工具。当前 Linux 制作环境无法构建及实测 Windows exe。

二、你的电脑如何启动
1. 先在原来直接打开的 HTML 网页里点击“完整备份”，保存 JSON。不要先关闭或删除原网页。
2. 完整解压此包。Windows 需安装桌面版 Microsoft Office，当前 Windows 账号需有相应文件读取权限。
3. 你已经成功运行过 Office 测试脚本，通常已有所需 Python 与 pywin32。双击“启动工作台.bat”。
   如提示缺少 pywin32，可运行“安装本地检索依赖.bat”（首次安装需联网或公司提供离线 wheel）。原有网页和已配置环境日常运行无需联网。
4. 启动器会打开 http://127.0.0.1:8765 ，请保留黑色启动窗口。关闭该窗口会停止文档检索。
5. 在新打开的工作台中恢复第1步的 JSON 备份。确认数据、公式、个人资料完整后，再把新地址作为日常入口。
注意：原 file:// 网页与 http://127.0.0.1:8765 属于不同浏览器来源，保存区域相互独立；不会自动迁移。以后固定使用此启动器、同一浏览器和同一浏览器用户。不要通过其他端口或 localhost 替换地址。
直接双击“启动工程师工作台.html”仍可以离线使用原有生产数据功能，但无法调用本机 Office 文档检索。

三、检索步骤
1. 左侧“文档检索”→“选择文件夹”，或粘贴完整本地/公司共享文件夹路径。
2. 点击“建立索引/更新索引”。包括子文件夹的 .doc/.docx/.ppt/.pptx；跳过 Office 临时文件和指向其他位置的链接文件夹。
3. Office 可能显示授权、密码、文档修复或公司安全提示，请在本机确认。读取以只读打开，宏强制禁用；无法设置宏保护时不会打开该文件。
4. 多个关键词用空格分开；匹配同一文字片段中同时包含这些词的内容。支持中文、英文以及 Word/PPT 类型筛选。每页30处匹配。
5. 搜索结果标注来源相对路径及位置。“打开原文件”会按系统默认程序打开对应文档；请按标注的页码/段落查阅，本版不自动跳到指定位置。
6. 原文件有更新或新增时，点击“更新索引”。未变化文件根据修改时间和大小复用。改名/删除的文件会在完整更新后移除。修改时间或大小已变化的文件不会继续显示旧搜索内容，提示重新索引。
7. “取消任务”在当前 Office 文件读取结束后生效；已完成部分保存。完整更新前未到达的旧文件仍保留，但查询时会检查文件是否仍存在、是否变化。
8. “清空索引”只清理检索索引和所选资料库，不删除源文档或生产数据；运行任务时需先取消并等待结束。

四、保存、备份与分发
生产数据、公式、主题、个人资料等：保持原有浏览器自动保存与“完整备份/恢复备份”。定期备份，重要修改后也保存一份。
文档检索索引：每次任务结束自动保存在当前 Windows 用户的 %LOCALAPPDATA%\ProcessEngineerWorkbench\DocumentSearch\index.dat，使用 Windows DPAPI 加密，绑定当前用户/电脑。不写入工作台 ZIP，不包含在网页 JSON 备份中，不供同事共用；换电脑或账号后重新建立即可。
索引保存失败会在界面明确提示；本次仍可检索，但下次需要重建。清空索引同时删除上述本地缓存。
发送此源代码包：同事需要 Python、pywin32 和 Office。
发送已打包 Windows 便携包：同事不需要安装 Python，但仍需 Microsoft Office、公司的解密客户端及自己的文档权限。打包程序能否被公司加密策略允许，必须在目标电脑重新测试；Python 能读并不保证 exe 一定有同样权限。
同事不会获得你浏览器中的生产数据、文档目录或检索索引。需要交接生产数据时，另发经授权的 JSON 备份。

五、Windows 一键打包（你打包一次，同事解压使用）
1. 在 Windows 构建电脑上安装 Python，并在同一个 Python 环境安装 pywin32、PyInstaller；需要联网或公司提供离线安装包。
   命令：python -m pip install pyinstaller pywin32
2. 双击“打包Windows启动器.bat”。工具只生成程序，不读取任何资料文件夹，不会把个人索引或浏览器数据打包。
3. 成功后得到 Windows-Build\Workbench-Windows-Portable.zip。
4. 先自己解压并运行其中 ProcessEngineerWorkbench.exe，再在一台未安装 Python 的 Windows 电脑上测试。还需检查公司加密文件授权读取。
5. 验证后，把整个便携 ZIP 发给同事。同事完整解压后双击 exe。必须保留 _internal 等配套文件，不能只发 exe。
构建架构随 Python，例如64位 Python 生成64位程序。建议与实际使用电脑架构一致。公司软件策略可能要求签名或白名单，请按公司正常流程使用。

六、范围和排查
- 当前检索 Word 正文（含正文表格）及 PPT 页面文字、页面表格、组合形状文字；不包含图片 OCR、扫描页、PPT 备注、Word 页眉页脚、嵌入附件。
- 不是 AI 问答：结果为关键词检索到的原文片段，需要回原文件核对。
- 每次最多3000份文件，每份不超过100MB，每份最多200万文字；超过限制或部分索引会明确提示。请选择具体业务资料夹，避免一次扫描整个磁盘。
- 不能读取密码保护或当前账号无权读取的文档；不会尝试破解。
- 长时间停留：检查 Office 授权或密码弹窗；取消为协作式，不会强杀 Office 或关闭你已打开的其他文档。
- 提示8765端口占用：检查是否已启动工作台；如没有，请关闭占用程序后重试。为保持浏览器数据位置，不会自动换端口。
- 断开连接：保留启动窗口，刷新页面；若重启过启动器，旧页面需要刷新以取得新会话。
- 找不到关键词：确认索引完成、类型筛选正确、文件未更新、内容确实是可选中文字而非图片；可先搜索短词。
- 读取错误只显示文件名与通用原因，不将文档内容输出到日志。正文仍可在本机 Office 中正常查看。

七、验证边界
原有前端功能可在本次构建中自动测试；本地索引、查询、增量更新、访问校验可用模拟读取器验证。实际 Windows COM、DPAPI、系统文件夹窗口和 exe 需在你的 Windows 环境验证；本包没有宣称已经完成这些实机验证。
